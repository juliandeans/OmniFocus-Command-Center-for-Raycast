# Security Policy

## Supported Versions

Only the latest release and the latest commit on the `main` branch are actively supported with security updates.

| Version               | Supported          |
| --------------------- | ------------------ |
| Latest release / main | :white_check_mark: |
| Older releases        | :x:                |

## Reporting a Vulnerability

Please **do not** open a public GitHub issue, pull request, or public discussion for security vulnerabilities.

### Preferred Reporting Channel

Please report security issues responsibly using **GitHub Private Vulnerability Reporting**:

1. Navigate to the repository's **Security** tab on GitHub.
2. Click **Report a vulnerability** under "Vulnerability reporting".
3. Provide details according to the template below.

> [!NOTE]
> **Maintainer Note**: GitHub Private Vulnerability Reporting must be enabled in repository **Settings → Code security and analysis → Private vulnerability reporting** once the repository is made public.

### What to Include in Your Report

To help reproduce and resolve the issue promptly, please provide:

- **Extension Version**: (e.g. 1.0.0 or git commit hash)
- **Raycast Version**: (from Raycast → Settings → About)
- **OmniFocus Version**: (from OmniFocus → About OmniFocus, including Pro status)
- **macOS Version**: (from Apple menu → About This Mac)
- **Reproduction Steps**: A clear, step-by-step description of how to trigger the issue using synthetic or dummy data.
- **Expected Behavior**: What you expected to happen.
- **Actual Behavior**: What actually happened.

### Data Privacy in Security Reports

> [!IMPORTANT]
> **Never include real, private, or sensitive OmniFocus data** (such as real task titles, private notes, client names, passwords, or personal project structures) in vulnerability reports, logs, or screenshots. Always reproduce issues using disposable dummy data.
